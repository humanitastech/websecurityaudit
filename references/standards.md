# Sources and normative selection

Sources consulted during creation: 2026-10-12. Revalidate versions and amendments during each use; links do not guarantee future validity.

## ENS

- [Royal Decree 311/2022, consolidated BOE text](https://www.boe.es/eli/es/rd/2022/05/03/311/con): consult scope, principles, requirements, categorization, measures, and assessment procedures. Use Annexes I, II, and III for specific decisions; record identifiers only after checking the text.
- [ENS portal — conformity](https://ens.ccn.cni.es/es/conformidad): consult the declaration/certification process applicable to the category. Do not issue official declarations or conformity badges through this skill.
- [CCN — updates to guides 801, 802, 803, 805, and 808](https://www.ccn.cni.es/es/actualidad-ccn/1282-actualizacion-de-cinco-guias-ccn-stic-de-la-serie-800-conforme-al-real-decreto-311-2022-y-a-los-nuevos-retos-de-la-ciberseguridad): locate current guidance on responsibilities, auditing, categorization, policy, and verification. Distinguish CCN guidance from normative obligations and specific profiles.

## ISO

Select only standards useful for assessing the system. The descriptions below guide selection; they are neither reproductions nor official mappings of the standards.

| Starting reference | Assessment use |
| --- | --- |
| [ISO/IEC 27001:2022](https://www.iso.org/standard/27001) | Security management: ISMS scope, responsibilities, risk treatment, evidence, and improvement. Check current amendments. A website review does not assess the entire ISMS. |
| [ISO/IEC 27002:2022](https://www.iso.org/standard/75652.html) | Guidance for selecting and implementing relevant organizational and technical controls. |
| [ISO/IEC 27005:2022](https://www.iso.org/standard/80585.html) | Structure risk assessment and treatment. |
| [ISO/IEC 27034-1:2011](https://www.iso.org/standard/44378.html) | Application security concepts and management; select other parts only when relevant and verified. |

Consider additional cloud, privacy, continuity, or testing standards only when justified by context, verifying their edition and scope in the official catalog. Do not present an indiscriminate list as mandatory.

For specific clauses, use a licensed copy legitimately provided by the user or accessible official content. Record the level of source access. Avoid extensive reproduction of copyrighted standards; provide original analysis and brief references. If an ISO standard is contractually or legally binding in the particular case, record that obligation separately and address requirements cumulatively.
